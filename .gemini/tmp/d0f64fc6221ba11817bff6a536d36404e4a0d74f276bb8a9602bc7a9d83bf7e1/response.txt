Thank you for providing the output from `check_font.php`. The message "ERROR: GD FreeType support is NOT enabled in your PHP installation" is very specific and points to the exact problem.

This means that while the GD library is enabled (which is why `imagecreatetruecolor` now works), it does **not** have the necessary FreeType support compiled in or enabled. FreeType is essential for working with TrueType Font (`.ttf`) files, like `Roboto-Regular.ttf`.

To address this, please try the following:

1.  **Re-open your `php.ini` file** again via the XAMPP Control Panel (Apache "Config" -> `php.ini`).
2.  Carefully examine the "Dynamic Extensions" section. You might have uncommented `extension=gd` (or `extension=php_gd.dll`).
3.  **Look for other `gd` related lines.** Sometimes, different PHP versions or XAMPP builds include alternative GD extensions that might have FreeType support. For instance, you might find:
    ```ini
    ;extension=php_gd2.dll
    ```
    If you find an alternative `gd` extension (like `php_gd2.dll` or similar), try this:
    *   **Comment out** the currently active `extension=gd` (add a `;` in front of it).
    *   **Uncomment** the alternative `gd` extension (remove the `;` in front of it).
4.  Also, **search the entire `php.ini` file for "FreeType"** or "ttf". While less common, there might be a specific `extension=freetype` or a configuration directive that needs to be set.
5.  **Save** the `php.ini` file.
6.  **Restart Apache** from the XAMPP Control Panel.

After restarting Apache, please run the diagnostic script once more: **http://localhost/s21af/public/check_font.php**

If, after trying different `gd` extensions, you still get the "GD FreeType support is NOT enabled" error, it might indicate that your current XAMPP installation's PHP build does not have GD compiled with FreeType. In that (less common) scenario, upgrading your XAMPP to a more recent version might be the only solution.

Please provide the full output after these steps.
